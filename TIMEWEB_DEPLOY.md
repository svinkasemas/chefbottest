# ☁️ TIMEWEB_DEPLOY.md — постоянный запуск ChefBot на Timeweb Cloud

Эта инструкция — продолжение `INSTALL.md`, когда вы уже проверили бота
локально (например, через ngrok) и хотите, чтобы он работал постоянно,
24/7, без вашего компьютера.

Понадобится: аккаунт на [timeweb.cloud](https://timeweb.cloud/), способ
оплаты (карта РФ, СБП, ЮMoney и т.д.) и свой домен (можно купить там же
или у другого регистратора — без домена HTTPS не выпустить).

⚠️ **Копируйте и вводите команды по одной строке**, каждый раз дожидаясь
её завершения. Не копируйте строки с тремя обратными кавычками `` ``` `` —
это разметка Markdown (обозначение блока кода в тексте), а не часть
команды; если она попадёт в терминал — увидите ошибку про «неизвестный
командлет» на этих символах.

## 1. Что покупать

**Виртуальный сервер (VDS/VPS).** В панели Timeweb это раздел «Облачные
серверы». Для нашего проекта (лёгкий FastAPI-бэкенд + один Telegram-бот,
без больших нагрузок) с запасом хватит:

- **1 vCPU, 1 ГБ RAM, 15–20 ГБ NVMe**, ОС — **Ubuntu 22.04 LTS** (или 24.04).

При создании сервера в панели среди тарифов по умолчанию показываются
довольно крупные конфигурации (например, от 900 ₽/мес за 2 vCPU / 2 ГБ).
Для такого маленького проекта это избыточно — при создании сервера
выберите вариант **«Произвольная»** конфигурация (в панели рядом со
списком готовых тарифов) и вручную поставьте 1 vCPU / 1 ГБ RAM — это
будет заметно дешевле. Точную цену панель показывает сразу, до оплаты, —
сверьтесь с ней перед подтверждением. Тарификация у Timeweb почасовая, то
есть тестировать можно, не платя сразу за целый месяц.

**Домен.** Нужен обязательно — Telegram Mini App не откроется по IP-адресу
или без https. Купить можно прямо в Timeweb (раздел «Домены») или у
любого другого регистратора (reg.ru, ru-center и т.п.) — не принципиально,
где, главное — потом направить его на IP вашего сервера (шаг 6). Домен
третьего уровня (поддомен, если у вас уже есть свой домен) тоже подойдёт.

**Больше ничего покупать не нужно** — SSL-сертификат для HTTPS выпускается
бесплатно и автоматически (Let's Encrypt через Caddy, настроим в шаге 6).

## Шаг 1. Регистрация и создание сервера

1. Зарегистрируйтесь на [timeweb.cloud](https://timeweb.cloud/) (кнопка
   «Создать аккаунт»), пополните баланс на небольшую сумму для старта.
2. В панели откройте раздел **«Облачные серверы»** → **«Создать»**.
3. На первом шаге выберите ПО: **«Чистая» операционная система** →
   **Ubuntu 22.04** (или 24.04).
4. Выберите локацию — для аудитории из СНГ подойдёт **Москва** или
   **Санкт-Петербург** (для Telegram-бота разница в скорости отклика из-за
   региона сервера минимальна — сам Telegram работает через свои сервера
   по всему миру).
5. Выберите тариф — конфигурацию **«Произвольная»**, поставьте 1 vCPU /
   1 ГБ RAM / 15–20 ГБ NVMe (см. раздел выше).
6. Способ входа: выберите **«Пароль»** (проще для начала — пароль root
   покажется в панели после создания) либо, если знакомы с SSH-ключами,
   добавьте свой публичный ключ — это безопаснее.
7. Дайте серверу имя (например, `chefbot`) и нажмите **«Создать»**.

Через 1–2 минуты сервер будет готов. На странице сервера (Дашборд) вы
увидите **IP-адрес** и **пароль root** — сохраните их, они понадобятся
дальше.

## Шаг 2. Первое подключение к серверу

Два варианта — выберите любой:

**А. Веб-консоль в панели (ничего дополнительно ставить не нужно).**
На странице сервера найдите кнопку «Консоль» — откроется терминал прямо в
браузере, уже подключённый к серверу.

**Б. Подключение по SSH с компьютера.** Windows 10/11 и macOS уже умеют
`ssh` из коробки. В PowerShell или терминале:
```
ssh root@ВАШ_IP_АДРЕС
```
Подтвердите подключение (`yes`) при первом разе, затем введите пароль
root из панели (при вводе пароля символы не отображаются — это нормально).

## Шаг 3. Базовая настройка сервера

Все команды ниже выполняются на сервере (после подключения по SSH),
**по одной**, дожидаясь завершения каждой:

```
apt update && apt upgrade -y
apt install -y python3 python3-venv python3-pip git ufw
```

Настройте базовый файрвол, чтобы сервер был доступен только по нужным
портам:
```
ufw allow 22
ufw allow 80
ufw allow 443
ufw enable
```
На вопрос про подтверждение — введите `y` и Enter.

Проверьте версию Python (на Ubuntu 22.04/24.04 обычно уже подходящая):
```
python3 --version
```
Если версия ниже 3.11 — на Ubuntu 22.04 это нормально (там 3.10), проект
всё равно будет работать, конфликтов зависимостей, как на Windows с
Python 3.14, здесь не будет: на Linux для всех нужных пакетов есть готовые
сборки под любую актуальную версию Python.

## Шаг 4. Перенос проекта на сервер

Самый простой для новичка способ — через графическую программу
**[WinSCP](https://winscp.net/eng/download.php)** (Windows) или **Cyberduck**
(macOS): подключаетесь к серверу по тем же данным (IP, `root`, пароль),
что и в SSH, и перетаскиваете папку `RecipeApp` (без папки `venv`, если
она у вас есть локально — на сервере окружение будет отдельное) в `/root/`
или `/opt/`.

Альтернатива — если ваш код уже лежит на GitHub, на сервере проще всего:
```
git clone https://github.com/ВАШ_АККАУНТ/ВАШ_РЕПОЗИТОРИЙ.git /opt/chefbot
```

Дальше в этой инструкции путь к проекту на сервере обозначен как
`/opt/chefbot` — подставьте свой, если положили в другое место.

## Шаг 5. Установка зависимостей и первый запуск

На сервере, по одной команде:
```
cd /opt/chefbot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Настройте `.env` (на сервере, не тот, что на вашем компьютере):
```
cp .env.example .env
nano .env
```
В `nano` впишите `BOT_TOKEN`, `ADMIN_IDS`, а `WEBAPP_URL` пока оставьте —
вернёмся к нему в шаге 8, когда домен уже будет привязан. Сохранить в
`nano`: `Ctrl+O`, затем `Enter`, выйти — `Ctrl+X`.

Наполните базу рецептами:
```
python -m scripts.seed_db
```

Проверьте, что backend в принципе запускается:
```
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```
Если видите `Application startup complete` — всё в порядке, остановите
командой `Ctrl+C` (постоянный запуск настроим через systemd в шаге 7).

## Шаг 6. Домен и HTTPS через Caddy

### 6.1. Направьте домен на сервер

В панели управления доменом (Timeweb или другой регистратор) откройте
настройки DNS и добавьте запись:

| Тип | Имя | Значение |
|-----|-----|----------|
| A   | `@` (или поддомен, например `bot`) | IP-адрес вашего сервера |

Изменения DNS распространяются не мгновенно — обычно от нескольких минут
до пары часов.

Проверить, что домен уже указывает на сервер, можно с любого компьютера:
```
ping ваш-домен.ru
```
В ответе должен быть IP-адрес вашего сервера.

### 6.2. Установите Caddy — он сам получит бесплатный HTTPS-сертификат

На сервере, по одной команде:
```
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update
apt install -y caddy
```

Откройте конфигурацию Caddy:
```
nano /etc/caddy/Caddyfile
```
Удалите всё содержимое и впишите (замените на свой домен):
```
ваш-домен.ru {
    reverse_proxy localhost:8000
}
```
Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`) и перезапустите Caddy:
```
systemctl reload caddy
```

Caddy сам обратится к Let's Encrypt и выпустит сертификат при первом
запросе к домену — никаких дополнительных действий не нужно.

## Шаг 7. Автозапуск через systemd

Чтобы backend и бот работали постоянно (и сами перезапускались при сбое
или перезагрузке сервера), оформим их как systemd-сервисы.

Backend:
```
nano /etc/systemd/system/chefbot-backend.service
```
Содержимое (замените `/opt/chefbot` на свой путь):
```
[Unit]
Description=ChefBot backend (FastAPI)
After=network.target

[Service]
WorkingDirectory=/opt/chefbot
ExecStart=/opt/chefbot/venv/bin/uvicorn backend.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

Бот:
```
nano /etc/systemd/system/chefbot-bot.service
```
Содержимое:
```
[Unit]
Description=ChefBot Telegram bot
After=network.target chefbot-backend.service

[Service]
WorkingDirectory=/opt/chefbot
ExecStart=/opt/chefbot/venv/bin/python -m bot.bot
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

Включите и запустите оба сервиса:
```
systemctl daemon-reload
systemctl enable --now chefbot-backend chefbot-bot
```

Проверить, что всё работает:
```
systemctl status chefbot-backend
systemctl status chefbot-bot
```
В выводе должно быть `active (running)` зелёным. Логи в реальном времени
(удобно для отладки):
```
journalctl -u chefbot-backend -f
journalctl -u chefbot-bot -f
```
(выход из просмотра логов — `Ctrl+C`).

## Шаг 8. Обновить .env и BotFather

Теперь, когда домен привязан и HTTPS работает, откройте `.env` на сервере
ещё раз:
```
nano /opt/chefbot/.env
```
Впишите:
```
WEBAPP_URL=https://ваш-домен.ru/
DEV_MODE=false
```
Сохраните и перезапустите бота, чтобы он подхватил новый адрес:
```
systemctl restart chefbot-bot
```

Дальше — как в `INSTALL.md`, шаг 8: в **@BotFather** → `/mybots` → ваш
бот → `Bot Settings` → `Menu Button` → `Configure Menu Button` → укажите
`https://ваш-домен.ru/`.

Откройте бота в Telegram, отправьте `/start`, проверьте, что приложение
открывается.

## Обслуживание проекта

**Как обновить код после изменений.** Если переносили файлы через WinSCP —
загрузите изменённые файлы поверх старых, затем:
```
systemctl restart chefbot-backend chefbot-bot
```
Если через git — на сервере:
```
cd /opt/chefbot
git pull
systemctl restart chefbot-backend chefbot-bot
```

**Как посмотреть логи после сбоя:**
```
journalctl -u chefbot-backend -n 100 --no-pager
journalctl -u chefbot-bot -n 100 --no-pager
```

**Резервное копирование базы данных.** `database.db` — обычный файл.
Проще всего — в панели Timeweb на странице сервера включить автоматические
бэкапы всего сервера («Резервное копирование» в Дашборде). Ручной вариант —
периодически копировать файл к себе:
```
scp root@ВАШ_IP:/opt/chefbot/database.db ./backup-$(date +%Y%m%d).db
```
(выполняется с вашего компьютера, не на сервере).

**Как добавлять новые рецепты** — так же, как в `README.md`: через
`/admin` в боте или через `data/seed_recipes.json` + `python -m scripts.seed_db`
на сервере.

## Решение проблем

**После `systemctl enable --now chefbot-backend` статус `failed`**
→ Смотрите точную причину: `journalctl -u chefbot-backend -n 50 --no-pager`.
Чаще всего — опечатка в пути `WorkingDirectory`/`ExecStart` в файле
сервиса, или не выполнен `pip install -r requirements.txt` в `venv` на
сервере.

**Домен открывается, но сертификат не выпускается / браузер пишет "небезопасно"**
→ Проверьте, что DNS уже распространился (`ping ваш-домен.ru` показывает
IP сервера) и что порты 80 и 443 открыты и в `ufw`, и в панели Timeweb
(раздел «Настройки сети» на странице сервера — там тоже может быть
отдельный файрвол). Затем: `systemctl reload caddy` и подождите минуту.

**`Address already in use` при запуске uvicorn**
→ Порт 8000 уже занят предыдущим запуском. Найдите и остановите: 
`systemctl stop chefbot-backend`, затем запустите заново, либо
`fuser -k 8000/tcp` чтобы принудительно освободить порт.

**Бот отвечает, но кнопка Mini App не открывается / показывает старую версию**
→ Проверьте `WEBAPP_URL` в `.env` на сервере и в настройках Menu Button у
BotFather — оба значения должны совпадать и быть актуальным доменом.
После правки `.env` не забудьте `systemctl restart chefbot-bot`.

**Не получается зайти по SSH: `Connection refused` или зависает**
→ Проверьте в панели Timeweb, что сервер запущен (не выключен), и что вы
используете актуальный IP-адрес с Дашборда. Как запасной вариант — всегда
можно зайти через встроенную веб-консоль в панели, ей не мешают проблемы
с сетью на вашей стороне.
