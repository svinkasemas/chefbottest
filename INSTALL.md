## 1. Что понадобится

- **Python версии 3.11 или 3.12** (проверить: `python3 --version` в
  терминале / `python --version` в командной строке Windows).
  ⚠️ Специально не берите самую новую версию (3.13/3.14): для неё у многих
  библиотек ещё нет готовых сборок под Windows, из-за чего установка
  зависимостей падает с ошибками компиляции (`Microsoft Visual C++ 14.0
  or greater is required`, `linker link.exe not found` и т.п.) — подробнее
  в специальном разделе ниже, если уже с этим столкнулись. 3.11/3.12 —
  самый надёжный выбор на сегодня.
- Аккаунт в Telegram
- 15–20 минут свободного времени

Проверить версию Python:

```
python3 --version
```

При установке на Windows обязательно поставьте галочку
**"Add Python to PATH"**.

### Если у вас уже стоит Python 3.13/3.14 (новый Python Install Manager)

Если в выводе `pip install` встречаются пути вида
`...\AppData\Local\Python\pythoncore-3.14-64\...` — у вас установлен новый
официальный **Python Install Manager** (команда `py`). Это удобно: он умеет
держать несколько версий Python одновременно, и 3.12 можно поставить
рядом, ничего не удаляя:

```
py install 3.12
py list
```

Вторая команда должна показать в списке `3.12` — дальше в шаге 2
используем именно эту версию (`py -3.12 -m venv venv`), не трогая
установленный 3.14.

## Шаг 1. Получить токен бота

1. Откройте Telegram, найдите **@BotFather**.
2. Отправьте команду `/newbot` (или используйте уже существующего бота).
3. Придумайте имя и username бота (username обязательно заканчивается на `bot`,
   например `chefbot_helper_bot`).
4. BotFather пришлёт токен вида:
   ```
   123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
   Скопируйте и сохраните его — понадобится в шаге 3.
5. Узнайте свой Telegram ID: напишите **@userinfobot**, он пришлёт число
   вида `987654321`. Тоже сохраните — это понадобится, чтобы получить
   доступ к админ-панели бота.

## Шаг 2. Скачать проект и установить зависимости

Распакуйте архив `ChefBotApp.zip`. Внутри будет папка **`RecipeApp`** —
это и есть корень проекта (в ней лежат `backend`, `bot`, `webapp`,
`requirements.txt` и т.д.).

**Откройте терминал именно внутри этой папки.** Проще всего — зайти в
папку `RecipeApp` через проводник/Finder и там, зажав Shift, кликнуть
правой кнопкой → «Открыть окно PowerShell здесь» (Windows) или открыть
Терминал из контекстного меню (macOS).

Проверьте, что вы там, где нужно — команда должна показать файл
`requirements.txt`:

macOS / Linux:
```
ls requirements.txt
```

Windows (PowerShell):
```
dir requirements.txt
```

Если появилась ошибка «файл не найден» — значит, вы не в той папке.
**Не выполняйте `cd RecipeApp`, если вы уже находитесь внутри `RecipeApp`**
— это частая причина ошибки `cd : Не удается найти путь`
(получится вложенная несуществующая `RecipeApp\RecipeApp`).

Дальше — создание виртуального окружения, чтобы зависимости проекта не
смешивались с остальным Python на компьютере.

**Важно:**
- Копируйте и вводите команды **по одной строке**, каждый раз нажимая
  Enter и дожидаясь, пока команда закончится, прежде чем вводить следующую.
- **Не копируйте строки с тремя обратными кавычками `` ``` ``** — это
  разметка Markdown (обозначает начало/конец блока кода в тексте
  инструкции), а не часть команды. Если в терминал случайно попали
  символы `` ` `` и PowerShell пишет на них ошибку — значит, вы скопировали
  лишнее; закройте терминал, откройте новый и скопируйте только сам текст
  команды.

**macOS / Linux** (три отдельные команды, вводить по одной):
```
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

**Windows (PowerShell), если у вас Python 3.11 или 3.12** (три отдельные
команды, вводить по одной):
```
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

**Windows (PowerShell), если у вас новый Python Install Manager и Python 3.14**
(см. раздел выше — вы уже поставили 3.12 командой `py install 3.12`).
Используйте `py -3.12` вместо `python`, чтобы окружение создавалось именно
на 3.12, а не на 3.14 (тоже три отдельные команды):
```
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если в конце вывода последней команды видите строку `Successfully
installed ...` — всё установилось, **на этом шаг 2 завершён**, дальше
переходите к шагу 3. Не запускайте команды создания окружения ещё раз —
если сейчас в начале строки терминала написано `(venv)`, окружение уже
активно и всё уже установлено.

После команды создания окружения (`python -m venv venv` / `py -3.12 -m venv venv`)
можно, при желании, проверить, что оно правда создалось, прежде чем
активировать:

```
dir venv\Scripts\Activate.ps1
```

Если PowerShell отвечает `Не удается найти путь` — значит, окружение не
создалось (например, из-за проблемы с самим Python). Удалите пустую/битую
папку и создайте заново — но только если вы **не находитесь** внутри уже
активированного окружения в этом же терминале (если строка начинается с
`(venv)`, сначала введите `deactivate`, иначе получите
`Permission denied` — Windows не даёт перезаписать файл `python.exe`,
которым в этот момент пользуется сам терминал):
```
deactivate
Remove-Item -Recurse -Force venv
py -3.12 -m venv venv
```

⚠️ В PowerShell важно писать активацию именно так: **`.\venv\Scripts\Activate.ps1`**
(с точкой-слэшем в начале и расширением `.ps1`). Команда `venv\Scripts\activate`
без этого — частая причина ошибки `Не удалось загрузить модуль "venv"`:
PowerShell пытается воспринять её как имя модуля, а не как путь к скрипту.
Если же PowerShell отвечает `не распознано как имя командлета` именно на
`.\venv\Scripts\Activate.ps1` — значит, файл `Activate.ps1` физически
отсутствует, то есть само окружение не создалось (см. проверку выше).

Если вместо этого PowerShell пишет что-то вроде
`выполнение сценариев отключено в этой системе` — значит, включена
политика безопасности, запрещающая запуск скриптов. Разово разрешите её
для текущего окна PowerShell (не потребует прав администратора):
```
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```
и затем повторите `.\venv\Scripts\Activate.ps1`.

После успешной активации в начале строки терминала появится `(venv)` —
это признак того, что окружение активно. Проверьте, что используется
именно нужная версия:
```
python --version
```
должно показать `3.11.x` или `3.12.x`, а не `3.14.x`.

Если `pip install -r requirements.txt` в конце вывода пишет `ResolutionImpossible`
или `conflicting dependencies` — вероятно, вам достался архив со старой
версией `requirements.txt`. Откройте `requirements.txt` и убедитесь, что
строка с pydantic выглядит так: `pydantic>=2.4.1,<2.10` (без знака `==`,
то есть без жёсткой фиксации версии). Если там `pydantic==2.10.4` —
замените вручную на `pydantic>=2.4.1,<2.10` и запустите установку заново.

Если вместо этого установка падает с ошибками сборки (`Building wheel for
pydantic-core ... error`, `Microsoft Visual C++ 14.0 or greater is
required`, `linker link.exe not found`) — вы, скорее всего, всё ещё
устанавливаете в окружение на Python 3.13/3.14, для которого нет готовых
сборок этих пакетов. Проверьте командой `python --version` внутри
активированного окружения — если версия 3.13/3.14, пересоздайте venv
через `py -3.12`, как описано выше.

Если всё прошло без ошибок — в конце вывода будет строка вида
`Successfully installed ...` и не будет строк `ERROR`.

> После этого шага при каждом новом открытии терминала для работы с
> проектом сначала активируйте окружение (`source venv/bin/activate` или
> `.\venv\Scripts\Activate.ps1`), иначе команды `uvicorn` и `python -m bot.bot`
> не найдутся.

## Шаг 3. Настроить .env

Скопируйте файл `.env.example` в `.env`:

macOS / Linux:
```
cp .env.example .env
```

Windows (PowerShell):
```
copy .env.example .env
```

Откройте `.env` в любом текстовом редакторе и заполните:

```env
BOT_TOKEN=123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx   ← токен из шага 1
ADMIN_IDS=987654321                                          ← ваш id из шага 1
WEBAPP_URL=https://your-domain.example.com/                  ← заполним в шаге 5
DEV_MODE=false
CORS_ORIGINS=*
```

Пока оставьте `WEBAPP_URL` как есть — вернёмся к нему в шаге 5.

## Шаг 5. Получить HTTPS-адрес (самое важное)

**Telegram открывает Mini App только по адресу, начинающемуся с `https://`.**
Обычный `http://localhost` не подойдёт даже для тестирования на своём
компьютере. Есть два пути:

### Вариант А — быстрая проверка через CloudPub (рекомендуется для старта)

⚠️ Если вы находитесь в России — **ngrok не будет работать** (блокирует
подключения по IP из-за санкций, ошибка `ERR_NGROK_9040`). Используйте
**[CloudPub](https://cloudpub.ru/)** — российский аналог с похожим
принципом работы.

1. Зарегистрируйтесь на [cloudpub.ru/dashboard](https://cloudpub.ru/dashboard),
   скопируйте токен со страницы личного кабинета.
2. Скачайте клиент для Windows (утилита командной строки) со страницы
   [cloudpub.ru/docs](https://cloudpub.ru/docs) и распакуйте, например, в
   `tools\cloudpub\` внутри папки проекта.
3. Привяжите аккаунт (один раз):
   ```
   .\tools\cloudpub\clo.exe login
   ```
4. После того как backend будет запущен на порту 8000 (см. шаг 6), в
   **отдельном** окне терминала выполните:
   ```
   .\tools\cloudpub\clo.exe publish http 8000
   ```
5. В выводе найдите адрес вида:
   ```
   Сервис опубликован: http://localhost:8000 -> https://wildly-suitable-fish.cloudpub.ru
   ```
6. Скопируйте `https://wildly-suitable-fish.cloudpub.ru` и вставьте его
   в `.env` как `WEBAPP_URL` (с завершающим слэшем `/`).
7. **Важно:** адрес меняется при каждом перезапуске туннеля. Каждый раз
   придётся обновлять `WEBAPP_URL` в `.env` и перезапускать бота (шаг 7).

**Чтобы не делать шаги 4–7 руками каждый раз** — используйте
`scripts\dev-tunnel.ps1`: он сам поднимает туннель, вытаскивает свежий
адрес, прописывает его в `.env` и перезапускает бота одной командой:
```
.\scripts\dev-tunnel.ps1
```
Остановить всё (туннель, backend, бота) после проверки:
```
.\scripts\dev-tunnel.ps1 -Stop
```
Подробности и требования — в комментариях внутри самого файла скрипта.

Если ngrok у вас всё же работает (вы не в стране под ограничениями) — он
тоже подойдёт, синтаксис аналогичен: `ngrok http 8000`.

### Вариант Б — постоянный адрес (для реальной эксплуатации)

Разверните `backend/` на любом хостинге с доменом и HTTPS-сертификатом:
Timeweb Cloud (см. [TIMEWEB_DEPLOY.md](TIMEWEB_DEPLOY.md)), Railway, Render,
Fly.io, VPS с Nginx/Caddy + Let's Encrypt и т.п.
Подробнее — в разделе [«Постоянный запуск»](#постоянный-запуск-без-ngrok) ниже.

## Шаг 6. Запустить backend

В первом окне терминала (с активированным `venv`, из папки `RecipeApp`):

```
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Ожидаемый вывод:
```
INFO:     Uvicorn running on http://0.0.0.0:8000
INFO:     Application startup complete.
```

Оставьте это окно открытым — сервер должен работать всё время, пока вы
пользуетесь приложением. Проверить, что всё работает, можно, открыв в
браузере `http://localhost:8000/api/categories` — должен появиться JSON со
списком категорий.

## Шаг 7. Запустить бота

Откройте **второе** окно терминала (снова активируйте `venv`!), из той же
папки `RecipeApp`:

```
python -m bot.bot
```

Ожидаемый вывод:
```
INFO Бот запускается...
```

Если видите ошибку про `WEBAPP_URL` — вернитесь к шагу 5 и убедитесь, что
адрес в `.env` действительно начинается с `https://` и не пустой.

## Шаг 8. Настроить кнопку меню у @BotFather

Бот сам пытается установить кнопку меню при запуске, но лучше проверить и
настроить вручную на случай сбоя:

1. Откройте **@BotFather** → `/mybots` → выберите вашего бота.
2. `Bot Settings` → `Menu Button` → `Configure Menu Button`.
3. Введите тот же адрес, что в `WEBAPP_URL` (например,
   `https://a1b2-93-100-1-1.ngrok-free.app/`).
4. Введите текст кнопки, например `ChefBot`.

## Шаг 9. Проверка

1. Откройте вашего бота в Telegram.
2. Отправьте `/start`.
3. Должно появиться приветствие и кнопка **«🍽 Открыть ChefBot»** —
   нажмите её.
4. Откроется мини-приложение с категориями рецептов.

Если приложение открылось, но вместо контента — пусто или ошибка, смотрите
раздел [«Решение проблем»](#решение-проблем).

### Доступ к админ-панели

Отправьте боту команду `/admin` (сработает только для ID из `ADMIN_IDS` в
`.env`). Там — статистика, рассылка и добавление новых рецептов через JSON
(шаблон бот пришлёт сам).

## Постоянный запуск (без ngrok)

Для реальной эксплуатации (не только тестирования) нужен сервер, который
работает постоянно и имеет свой домен с HTTPS.

📄 **Если разворачиваете на [Timeweb Cloud](https://timeweb.cloud/) —
используйте отдельную подробную инструкцию [TIMEWEB_DEPLOY.md](TIMEWEB_DEPLOY.md)**:
что именно покупать, пошаговое создание сервера в панели, настройка
HTTPS и автозапуска — с конкретными командами под этого провайдера.

Ниже — общая схема, подходящая для любого VPS-хостинга:

1. Купите/арендуйте VPS и домен (или используйте поддомен, если уже есть).
2. Настройте DNS А-запись домена на IP сервера.
3. Установите Python, склонируйте/скопируйте проект на сервер, выполните
   шаги 2–4 этой инструкции на сервере.
4. Поставьте перед `uvicorn` reverse-proxy с бесплатным HTTPS-сертификатом
   — проще всего через [Caddy](https://caddyserver.com/) (сам получает
   сертификат Let's Encrypt):
   ```
   your-domain.example.com {
       reverse_proxy localhost:8000
   }
   ```
5. Укажите `WEBAPP_URL=https://your-domain.example.com/` в `.env`.
6. Чтобы `uvicorn` и `bot.py` не завершались при закрытии терминала,
   запускайте их как systemd-сервисы (или через `screen`/`tmux` для
   быстрого варианта) — так они переживут перезагрузку сервера.

Альтернатива без своего сервера — облачные платформы с готовым HTTPS
из коробки (Railway, Render, Fly.io и т.п.): загружаете код, они сами
выдают вам `https://...` адрес — его и укажите в `WEBAPP_URL`.

## Решение проблем

**`OSError: [WinError 121] Превышен таймаут семафора` / бот не может подключиться к `api.telegram.org`**
→ Это сетевая блокировка/сильное замедление конкретно домена
`api.telegram.org` на уровне провайдера (сам Telegram-клиент её обходит
своими средствами, а обычное HTTP-соединение из Python — нет). Проверить:
```
Test-NetConnection api.telegram.org -Port 443
```
Если `TcpTestSucceeded : False` — решение — прокси именно для бота. В `.env`
добавьте строку (замените на свои данные; если продавец прокси дал строку
вида `хост:порт:логин:пароль`, соберите URL в таком порядке):
```
PROXY_URL=http://логин:пароль@хост:порт
```
Если прокси HTTP не работает — попробуйте заменить схему на `socks5://`
(зависит от того, какой тип прокси вам продали). Требуется установленный
пакет `aiohttp-socks` — он уже есть в `requirements.txt`, но если ставили
зависимости раньше этого пункта, выполните `pip install -r requirements.txt`
ещё раз. Прокси нужен только для бота (сам он ходит наружу к Telegram) —
backend и мини-приложение он не затрагивает.

**`Error: [Errno 13] Permission denied: '...\venv\Scripts\python.exe'`**
→ Вы находитесь внутри уже активированного окружения (строка терминала
начинается с `(venv)`) и пытаетесь пересоздать `venv` поверх самого себя —
Windows не даёт перезаписать файл `python.exe`, которым в этот момент
пользуется сам терминал. Сначала выполните `deactivate`, и только потом
`Remove-Item -Recurse -Force venv` и создание нового окружения. Также имейте
в виду: если `pip install -r requirements.txt` уже написал `Successfully
installed ...` — окружение и так готово, пересоздавать его не нужно,
переходите сразу к шагу 3.

**В терминале ошибки на строках с `` ` `` (обратными кавычками) или `` ``` ``**
→ Вы скопировали в терминал не только саму команду, но и markdown-разметку
из инструкции (тройные обратные кавычки, которыми в тексте обозначаются
блоки кода). PowerShell пытается выполнить их как команду и не находит
такую. Закройте терминал (или нажмите Ctrl+C), откройте новый и
скопируйте только текст самой команды, без строк из одних кавычек.

**`ResolutionImpossible` / `conflicting dependencies` при `pip install -r requirements.txt`**
→ В `requirements.txt` строка pydantic должна быть `pydantic>=2.4.1,<2.10`
(без `==`). Если видите `pydantic==2.10.4` — это старая версия файла,
исправьте строку вручную и запустите установку заново.

**Установка зависимостей зависает на сборке `aiohttp`/`pydantic-core` из исходников, или падает с ошибками `Microsoft Visual C++ 14.0 or greater is required` / `error: linker link.exe not found` / `maturin failed`**
→ Это значит, что окружение создано на слишком новой версии Python
(3.13/3.14), для которой у этих пакетов ещё нет готовых сборок под
Windows — pip пытается собрать их из исходников (aiohttp — на C, pydantic-core
— на Rust), а нужного компилятора (Visual C++ Build Tools / Rust) на
компьютере нет. **Самое простое решение — не ставить компиляторы, а
использовать Python 3.12:**
```
py install 3.12
```
Затем удалите старое окружение и создайте новое именно на 3.12:
```
Remove-Item -Recurse -Force venv
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```
Проверить, что активно нужное окружение, можно командой `python --version`
(должно быть 3.12.x). С 3.12 все зависимости ставятся из готовых файлов
(`.whl`) за секунды, без всякой компиляции.

**PowerShell: `.\venv\Scripts\Activate.ps1` — `не распознано как имя командлета`**
→ В отличие от ошибки «не удалось загрузить модуль» (это про неправильный
синтаксис без `.ps1`), эта ошибка означает, что файла `Activate.ps1`
физически не существует — то есть виртуальное окружение не создалось.
Проверьте: `dir venv\Scripts\Activate.ps1`. Если путь не найден — пересоздайте
окружение (см. пункт выше про Python 3.12) и вводите команды **по одной**,
дожидаясь завершения предыдущей, а не вставляя весь блок сразу — при
одновременной вставке нескольких команд консоль иногда «съедает» часть
ввода, и предыдущая команда не успевает отработать.

**`cd : Не удается найти путь "...\RecipeApp\RecipeApp"`**
→ Вы уже находитесь внутри папки `RecipeApp` и пытаетесь зайти в неё ещё
раз. Проверьте текущую папку командой `dir requirements.txt` (Windows)
или `ls requirements.txt` (macOS/Linux) — если файл находится, никакой
`cd RecipeApp` не нужен, продолжайте со следующей команды.

**`ModuleNotFoundError: No module named 'fastapi'` (или aiogram/sqlalchemy)**
→ Не активировано виртуальное окружение (в начале строки терминала должно
быть `(venv)`) или не выполнен `pip install -r requirements.txt`. Повторите шаг 2.

**Бот при `/start` пишет "Mini App пока не настроен"**
→ `WEBAPP_URL` в `.env` пустой или равен примеру из `.env.example`.
Заполните его реальным https-адресом (шаг 5) и перезапустите бота (шаг 7).

**Приложение открывается, но внутри пусто / ошибка сети**
→ Backend (шаг 6) не запущен или упал. Проверьте окно терминала с
`uvicorn` — там будет текст ошибки. Также проверьте, что ngrok-туннель
(если используете) всё ещё активен — бесплатные туннели ngrok закрываются
через некоторое время простоя.

**После перезапуска ngrok кнопка в Telegram ведёт на старый (нерабочий) адрес**
→ Это ожидаемо для бесплатного ngrok: адрес каждый раз новый. Обновите
`WEBAPP_URL` в `.env`, перезапустите бота (шаг 7) и обновите адрес в
BotFather (шаг 8).

**`401 Unauthorized` при обращении к API вручную через браузер**
→ Это нормально: API проверяет подпись Telegram и не откроется просто по
ссылке в браузере. Для отладки вне Telegram временно поставьте
`DEV_MODE=true` в `.env` и перезапустите backend — тогда авторизация
подменяется тестовым пользователем. **Не забудьте вернуть `DEV_MODE=false`
перед реальным использованием.**

**Порт 8000 уже занят**
→ Запустите на другом порту: `uvicorn backend.main:app --port 8001` — и не
забудьте использовать этот же порт в `ngrok http 8001`.

**Как обновить/добавить рецепты после установки**
→ См. раздел «Как добавлять рецепты» в `README.md`: через `/admin` в боте
(без кода) или массово через `data/seed_recipes.json` + `python -m scripts.seed_db`.

**Как посмотреть, что реально хранится в базе**
→ `database.db` — обычный файл SQLite. Открыть его можно бесплатной
программой [DB Browser for SQLite](https://sqlitebrowser.org/).

обычно прямо написано, чего не хватает.
